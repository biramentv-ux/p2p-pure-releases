# P2P Messenger за Windows

Десктоп версия на същото приложение, събрана с Tauri 2. Цялото уеб приложение е вътре в
пакета, затова работи без твоя компютър, без сайта и без тунела. Пакетът се събира в
GitHub Actions на чиста Windows машина (`.github/workflows/windows-desktop.yml`).

## Файлове за сваляне

| Файл | За кого | Бележка |
|---|---|---|
| `P2P-Messenger-Setup-x64.exe` | Повечето хора | Инсталатор. Слага програмата само за текущия потребител, без администраторски права. Добавя икона в старт менюто и деинсталация от „Настройки → Приложения“. Ако липсва WebView2, го сваля сам. |
| `P2P-Messenger-portable-x64.zip` | Без инсталиране | Разархивира се и се стартира. Нужен е WebView2 (вграден в Windows 11). |
| `P2P-Messenger-winget-manifests.zip` | winget | Манифести за инсталиране с една команда (виж „Инсталиране с winget“). |
| `SHA256SUMS.txt` | Проверка | Контролни суми на файловете. |

## Инсталиране

1. Свали `P2P-Messenger-Setup-x64.exe` и го стартирай.
2. Windows може да покаже **„Windows protected your PC“**, защото пакетът още не е подписан.
   Натисни **More info** (Повече информация), после **Run anyway** (Изпълни въпреки това).
3. Следвай стъпките на инсталатора. Програмата се отваря от старт менюто като „P2P Messenger“.

Проверка, че файлът не е подменен (PowerShell):

```powershell
Get-FileHash .\P2P-Messenger-Setup-x64.exe -Algorithm SHA256
```

Сравни резултата с реда в `SHA256SUMS.txt`.

## Инсталиране с winget

Идентификатор на пакета: `DyrakArmy.P2PMessenger`. Манифестите са със схема 1.10.0, за да
ги чете и winget 1.11.

**След като пакетът е приет в официалното хранилище** (виж „Публикуване в winget“):

```powershell
winget install DyrakArmy.P2PMessenger
```

Обновяване: `winget upgrade DyrakArmy.P2PMessenger`. Премахване: `winget uninstall DyrakArmy.P2PMessenger`.

**Преди това, от манифестите в Release-а** (еднократно включване, в PowerShell като администратор):

```powershell
winget settings --enable LocalManifestFiles
Expand-Archive .\P2P-Messenger-winget-manifests.zip -DestinationPath .\winget
winget install --manifest .\winget\manifests\d\DyrakArmy\P2PMessenger\0.7.0
```

winget проверява SHA256 на инсталатора спрямо манифеста, преди да го пусне.

## Публикуване в winget

1. Създай таг за изданието (виж „Ново издание“). CI качва инсталатора и манифестите в
   Release-а, после инсталира програмата през winget от самия Release, като проверка.
2. За автоматично изпращане към [microsoft/winget-pkgs](https://github.com/microsoft/winget-pkgs)
   добави в репото секрет `WINGET_TOKEN`: GitHub токен (classic) с право `public_repo`.
   **Settings → Secrets and variables → Actions → New repository secret.** Без него CI само
   прикача манифестите и нищо не изпраща.
3. CI отваря pull request с `wingetcreate`. Проверката в хранилището (сканиране на
   инсталатора, тестово инсталиране) и прегледът от модераторите отнемат от часове до
   няколко дни. Едва след сливането работи `winget install DyrakArmy.P2PMessenger`.

Пакетът още не е подписан. Хранилището не забранява неподписани инсталатори, но
сканирането може да ги задържи по-дълго. Ако искаш да изчакаш сертификата, просто не
добавяй `WINGET_TOKEN`.

## Изисквания

- Windows 10 или 11, 64-битов.
- Microsoft Edge WebView2. В Windows 11 е вграден. Инсталаторът го добавя, ако липсва,
  като за това е нужен интернет.

## Какво е различно от браузърната версия

- **Отключване:** вход с passkey в десктоп прозореца може да не е наличен (WebView2 не
  връща PRF тайната). Тогава приложението използва парола, както и в браузъри без PRF.
  След това можеш да включиш **Windows Hello** (виж по-долу). Възстановяването с 12-те
  думи работи навсякъде.
- **Данни:** шифрованият профил, контактите и историята са в
  `%LOCALAPPDATA%\bg.p2pmessenger.desktop`. Те не се споделят с профила в браузъра.
  За да ползваш същата идентичност, възстанови я с 12-те думи.
- **Без service worker:** обновленията идват с нов инсталатор, не автоматично.
- **Мрежа:** локалният режим (QR) не прави заявки към сървър. Демо режимът (стая с код) и
  краткият код изискват сигналния Worker и интернет.

## Отключване с Windows Hello

Само в програмата за Windows и само ако Windows Hello (лице, пръстов отпечатък или PIN) е
настроен. В браузъра, на Linux и на телефона опцията не се показва.

1. Отключи с паролата и отметни **„Включи Windows Hello … за следващите отключвания“**.
2. Windows пита за Hello два пъти (създава ключ и проверява, че подписът е стабилен).
3. При следващо отключване натискаш **„Отключи с Windows Hello“**. Бутонът
   **„Използвай паролата“** остава винаги; ако Hello откаже, приложението само предлага паролата.

Как работи: Windows пази RSA ключ (в TPM, ако има) с име `p2p-messenger-<хеш от did>`.
Приложението го моли да подпише фиксирано 32-байтово предизвикателство (SHA-256 от домейн,
did и случайна сол). RSA PKCS#1 v1.5 подписът е детерминиран, затова от него с HKDF-SHA256
се получава един и същ AES-256-GCM ключ, който шифрова **второ копие** на семето. Копието с
паролата не се променя, 12-те думи остават възстановяването. Тези две Tauri команди
(`windows_hello_status`, `windows_hello_sign`) са единствените, разрешени за прозореца
(`src-tauri/capabilities/default.json`); подписването приема само имена `p2p-messenger-…` и
само 32 байта.

### Заплахи: Windows Hello срещу парола

| Нападател | Само парола | Парола + Windows Hello |
|---|---|---|
| Открадната/копирана папка с данни (без компютъра) | Трябва да разбие паролата (PBKDF2 600 000) | Същото; Hello копието е безполезно без ключа в TPM/профила на Windows |
| Код, пуснат като същия потребител, докато не си там | Може да чете IndexedDB, да слага keylogger и да чака да въведеш паролата | Може да извика Hello за същия ключ, но Windows показва подкана и иска лице/пръст/PIN — без теб подписът не става. Може също да чака да отключиш и да чете паметта |
| Код като същия потребител, докато ти отключваш | Хваща паролата (keylogger) или семето от паметта | Хваща подписа/семето от паметта; паролата не се въвежда, затова не изтича |
| Друг потребител на същия компютър (без администратор) | Не може да чете профила ти | Същото; Hello ключовете са на потребител |
| Администратор / зловреден код със SYSTEM | Всичко | Всичко |
| Някой знае PIN-а ти за Windows | Нищо не печели | Отключва приложението на този компютър (PIN-ът е заместител на Hello) |

Изводи: Hello не прави приложението по-устойчиво срещу зловреден код като твоя потребител
— такъв код и сега вижда всичко, след като отключиш. Печели се удобство и това, че паролата
не се пише при всяко отключване. Губи се: който знае PIN-а ти за Windows и има компютъра,
може да отключи. Ако това не ти харесва, не включвай Hello. Подканата на Windows Hello от
десктоп приложение понякога се отваря зад прозореца — виж лентата на задачите.

## Подпис

CI подписва инсталатора и самата програма със `signtool` (и ги проверява със
`signtool verify`), когато собственикът добави секретите `WINDOWS_CERT_PFX_BASE64` и
`WINDOWS_CERT_PASSWORD`. Без тях стъпката се пропуска с бележка. Видове сертификати
(включително безплатни/евтини за отворен код: SignPath, Azure Trusted Signing, Certum) и
точните стъпки: [SIGNING.md](SIGNING.md). Предупреждението на SmartScreen изчезва веднага с
EV / Trusted Signing или постепенно с OV, докато подписаните издания натрупат репутация.

Проверка на подписа (PowerShell): `Get-AuthenticodeSignature .\P2P-Messenger-Setup-x64.exe`.
